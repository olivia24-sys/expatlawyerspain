# Where canonical URLs live

Written 21 July 2026. Plain-English map of every place the site's absolute URLs are set, so this doesn't need rediscovering.

## The canonical host is the bare domain

`https://expatlawyerspain.com`, with no www. Everything in this repo uses it and nothing uses www. The one deliberate exception is `functions/_lib/util.js` (around lines 57 and 71), which allowlists **both** hosts as valid production origins for the API. Leave that alone.

The www to apex 301 lives in **Cloudflare**, as a zone-level Redirect Rule. It is **not** in `_redirects` and not anywhere in this repo, so grepping the repo will never find it. See `aios/context/els/decisions.md`, entry dated 2026-07-21.

## This folder returns 403 in production. That is deliberate.

Everything under `/tools/` is blocked at the edge by a Cloudflare WAF custom rule, added 21 July 2026:

- **Rule name:** `block /tools/`
- **Expression:** `starts_with(http.request.uri.path, "/tools/")`
- **Action:** Block, which returns 403

**Nothing is broken.** If a future session curls `https://expatlawyerspain.com/tools/anything` and gets a 403, that is the rule working as intended, not a deploy failure or a missing file.

**Why it exists:** the repo root IS the served directory, so before this rule every file in here was publicly readable, including all the notes files and all four build scripts. Confirmed by curl on 21 July: six `.md` files and `build-money-pages.js` all returned 200. Nothing on the site links to `/tools/`, so the fix was free.

**What it does not affect:** the rule is scoped to the `expatlawyerspain.com` zone, so `expatlawyerspain-96m.pages.dev` previews still serve `/tools/` normally, and local builds are untouched. No runtime asset lives here. The calculator loads `/js/calc-engine.js` and `/js/itp-calculator.js`; the `legal-data/` files in this folder are build-time inputs that get baked into `/js/` at build time, never fetched by the browser. Verified after the rule went live: the ITP calculator returned an identical result with zero console errors and no network request to `/tools/`.

Like the redirect below, this rule lives only in the Cloudflare dashboard. Grepping the repo will not find it.

## Canonical tags: two sources

**1. Hard-coded in the page HTML (38 pages).** Sits in the `<head>`, usually around line 17 on root pages and line 22 on blog posts. Editing the page edits the canonical. Nothing regenerates these.

**2. Emitted by a generator (3 scripts).** These write `href="${canonical}"` into the pages they build, so editing their output by hand gets overwritten on the next build:

| Script | Builds | Canonical built at |
|---|---|---|
| `build-money-pages.js` | the 4 pillar pages | line 243 |
| `build-tool-pages.js` | `/itp-calculator-spain` and friends | line 409 |
| `build-blog-listings.js` | `/blog/` and the 7 category indexes | line 185 |

All three derive it as `` `${SITE}/${slug}` ``.

## The SITE constant

Four scripts each hold their own copy. There is no shared config, so a host change means editing all four:

- `build-money-pages.js:37`
- `build-tool-pages.js:43`
- `build-blog-listings.js:26`
- `build-widget-data.js:40`

`build-widget-data.js` also has a local variable called `canonical` around lines 127 to 130. That is a JSON dataset hash and has nothing to do with canonical URLs. Don't let a find-and-replace touch it.

## og:url

25 pages have it hard-coded, plus 2 generated (`build-money-pages.js:305`, `build-tool-pages.js:482`). 13 pages have a canonical but no og:url. For the 8 blog index pages that's by design, since `build-blog-listings.js`'s `head()` only emits a canonical. The other 5 (`spanish-legal-glossary.html`, `terms`, `privacy`, `cookie-policy`, `how-we-verify`) look like drift and are unfixed as of this writing.

## sitemap.xml

40 `<loc>` entries, part hand-written, part generated. The generated parts sit between HTML comment markers and get replaced wholesale on each build:

- `<!-- money-pages:start` … `<!-- money-pages:end -->`, written by `build-money-pages.js`
- `<!-- tool-pages:start` … `<!-- tool-pages:end -->`, written by `build-tool-pages.js`

Everything else, including **all blog post URLs**, is hand-maintained. `build-blog-listings.js` does not touch the sitemap, so a new blog post needs its sitemap entry added by hand.

## Everywhere else absolute URLs appear

- `robots.txt`, the `Sitemap:` line plus two llms.txt comment lines.
- `llms.txt` and `llms-full.txt`, both generated by the money and tool page builders.
- `_headers` line 47, where the CSP allowlists the bare domain in `script-src`, `style-src`, `img-src`, `font-src` and `connect-src`. www is deliberately not listed.
- JSON-LD, where only `itp-calculator-spain.html` (lines 41 and 52) carries absolute URLs, both generated by `build-tool-pages.js`. Every other schema block uses relative URLs.
- `embed/v1.js:29` (`DEFAULT_ORIGIN`), `widgets/v1/itp-calculator.js:30-32`, `widgets/v1/firm-directory.js:17`.
- `functions/_lib/widget-firms-data.js`, 72 URLs generated by `build-widget-data.js`.
- `tools/test/widget-framework.test.mjs`, where 9 assertions hard-code the bare origin. **Any host change breaks these tests.**

## Don't touch

`_legacy-site-copies/` holds four archived site generations with their own canonicals, sitemaps and robots.txt. Nothing there is served.
